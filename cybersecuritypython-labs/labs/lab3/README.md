Лабораторна робота № 3 --- REST API на FastAPI та SQLite
Мета роботи
Розробити REST API для керування категоріями та записами з використанням
FastAPI і SQLite, реалізувати валідацію вхідних даних,
фільтрацію, пошук, пагінацію, обробку помилок і транзакційне пакетне
додавання записів.
Варіант
- Номер варіанта: 7
- Значення поля value: тривалість реагування на інцидент у
  хвилинах.
- Статуси записів: new, in_progress, done.
Використані технології
- Python
- FastAPI
- Uvicorn
- SQLite
- Pydantic

Налаштування та запуск
Команди нижче потрібно виконувати з кореня репозиторію.
1. Створення віртуального середовища
Windows PowerShell:
python -m venv .venv
.\.venv\Scripts\Activate.ps1
Якщо залежності ще не встановлені, встановіть потрібні пакети:
python -m pip install fastapi uvicorn
Якщо в репозиторії є requirements.txt, рекомендовано використовувати
його:
python -m pip install -r requirements.txt
2. Ініціалізація бази даних
Початкове заповнення виконується командою:
python -m labs.lab3.seed
Скрипт додає до порожньої бази 3 категорії та 8 початкових записів.
Повторний запуск не повинен додавати дублікати: якщо база вже містить
дані, скрипт повідомляє про це та не змінює її.
Щоб почати з чистої бази, зупиніть сервер, зробіть резервну копію файлу
бази даних і лише тоді видаліть або перейменуйте його перед повторним
заповненням.
3. Запуск API
python -m uvicorn labs.lab3.main:app --reload --host 127.0.0.1 --port 8000
Після запуску документація API доступна за адресою:
- Swagger UI: http://127.0.0.1:8000/docs
- ReDoc: http://127.0.0.1:8000/redoc
Для зупинки сервера натисніть Ctrl+C.
Основні маршрути API
Службові маршрути
  Метод   Маршрут      Призначення
  GET   /ping      Перевірка доступності API
  GET   /student   Отримання даних студента та варіанта
Категорії
  Метод      Маршрут                       Призначення
  GET      /categories                 Отримати список категорій
  POST     /categories                 Створити категорію
  DELETE   /categories/{category_id}   Видалити порожню категорію
Категорію, що містить записи, видалити не можна.
Записи
  Метод      Маршрут                  Призначення
  GET      /records               Отримати список записів
  POST     /records               Створити запис
  GET      /records/{record_id}   Отримати запис за ID
  PUT      /records/{record_id}   Повністю оновити запис
  DELETE   /records/{record_id}   Видалити запис
  POST     /records/bulk          Пакетно створити записи
Маршрут GET /records підтримує фільтрування, пошук і пагінацію.
Доступні параметри включають:
- category_id --- фільтр за категорією;
- status --- фільтр за статусом;
- min_value --- мінімальне значення тривалості;
- q --- текст для пошуку в назві;
- limit --- кількість записів у відповіді;
- offset --- кількість записів, які потрібно пропустити.
Приклад запиту:
GET /records?category_id=1&status=done&min_value=30&limit=10&offset=0
Модель даних
Категорії
Категорія містить:
- id --- ідентифікатор;
- name --- унікальна назва категорії.
Записи
Запис містить:
- id --- ідентифікатор, який генерується базою даних;
- code --- унікальний код;
- title --- назва запису;
- category_id --- посилання на категорію;
- value --- тривалість реагування в хвилинах для варіанта 7;
- status --- статус new, in_progress або done.
Початкові дані визначені у labs/lab3/data/seed.json. Схема таблиць
зберігається у labs/lab3/schema.sql.
Валідація та обробка помилок
API перевіряє структуру та значення вхідних даних. Зокрема,
перевіряються обов'язкові поля, довжина рядків, допустимі статуси,
невід'ємність числового значення та наявність категорії.
Основні HTTP-коди відповідей:
  Код                                 Значення
  200 OK                            Запит виконано успішно
  201 Created                       Ресурс створено
  204 No Content                    Ресурс видалено без тіла відповіді
  404 Not Found                     Ресурс або категорію не знайдено
  409 Conflict                      Конфлікт, наприклад дубльований код
                                      або спроба видалити непорожню
                                      категорію
  422 Unprocessable Entity          Некоректні вхідні дані
Транзакції та збереження даних
Операції запису до бази даних виконуються з контролем транзакцій. У разі
помилки зміни відкочуються. Пакетне додавання через POST /records/bulk
має бути атомарним: якщо один із записів не проходить перевірку, жоден
запис із цього пакета не повинен залишитися в базі.
SQLite зберігає дані у файлі, тому коректно створені записи залишаються
доступними після перезапуску API.
Перевірка роботи
Для ручного тестування використовуйте Swagger UI (/docs).
Рекомендовано перевірити:
1. Отримання категорій і записів.
2. Створення, читання, оновлення та видалення записів.
3. Фільтрацію, пошук і пагінацію.
4. Відхилення невалідних даних.
5. Обробку повторних кодів і неіснуючих категорій.
6. Неможливість видалити категорію, яка містить записи.
7. Відкат пакетної операції, якщо один із записів невалідний.
8. Повторний запуск seed.py без додавання дублікатів.
9. Збереження записів після перезапуску сервера.
Синтаксичну перевірку Python-файлів можна виконати командою:
python -m compileall labs/lab3 shared
Примітки для Git
Рекомендовано не додавати до репозиторію віртуальне середовище .venv/,
кеші __pycache__/, файли *.pyc, локальні секрети .env та тимчасові
логи. Файл seed.json потрібно зберігати, оскільки він потрібен для
початкового заповнення бази.
Рішення щодо додавання lab3.sqlite3 приймайте відповідно до вимог
викладача: базу можна відтворити зі схеми та початкових даних, але іноді
готовий файл БД є частиною здачі.
